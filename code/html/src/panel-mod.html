MODULES

Parts of the firmware that live in the free flash behind the head: tick the ones you want, then Apply. Switching modules off needs no file, their flash becomes a gap; to pack the area (and to add modules) Apply with the install image (.ota): the area is written anew.

The modules are off: .
The guard switched them off so the board stays reachable. Fix what they need (or switch the heavy ones off), then start them again.
Memory
Dark blue: the statics of the modules (their .data and .bss, known exactly). Light blue: the heap they took when they started (measured then; what they allocate later is not counted). The statics go into the fixed pool first, the largest first, the rest into one heap block; nothing is kept in reserve. Yellow: almost everything is taken, the board still runs. Point at a module that is off to see what it would take (striped).
Modules
The modules come from the install image (.ota) of a release: from the disk, or From GitHub (the one of the build this board runs). Tick the modules, then Apply: when the image is of another head build, its head goes on first (the same install as ADMIN, OTA); then the board restarts without modules, takes the ticked ones from the file, writes them packed and restarts with them. Nothing starts or stops before the restart. Only switching off needs no file. Without the webui module the board keeps a small page with the same switches, modules.html.
